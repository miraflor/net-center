Network location & adaptive spatial representation

How net-center works

A central location is not necessarily the middle of a map. net-center finds locations that minimize travel distance through a network, either to serve all demand from a single center or to represent demand with several sites.

Two workflows, one network metric. The original command solves exact weighted 1-median, vertex 1-center and continuous absolute 1-center problems. The adaptive command adds grouped demand, edge-interior attachment, finite-candidate multi-site medians and explicit site-count selection. This page uses a small, deterministic synthetic example; its browser solver is a teaching implementation, not the Python library or a benchmark.

1-medianMinimum weighted total distanceVertices or restricted candidates
Vertex 1-centerMinimum worst accessVertices or restricted candidates (adaptive)

Start with one small network

We use ten vertices, ten positive-length links and six demand rows with total weight 11. All coordinates are synthetic projected metres. The point at J lies inside the original A–B road: inserting J splits the 100 m link into two 50 m links. All subsequent calculations use this augmented graph. Roads are undirected; no junction is created simply because drawn lines cross.

The worked sequence
  1. Attach demand and define shortest-path distances.
  2. Compute a weighted median and compare minimax centers.
  3. Find exact finite-candidate solutions for several site counts.
  4. Select a representation size using explicit criteria.
  5. Handle components, groups and access diagnostics.

1. Replace straight-line distance with network distance

dG(u,v) = minpaths π:u→v ∑e∈π ℓ(e)

A route from A to H has length 600 m (one shortest route is highlighted). The direct Euclidean distance is about 495 m, but that shortcut is not a road. The original and adaptive Python solvers use SciPy Dijkstra on a symmetric sparse graph. The browser uses all-pairs Floyd–Warshall only because this graph is tiny.

Demand connector costs are fixed per row. Median locations do not change when the fixed weighted connector sum is added. Minimax centers can change because individual offsets affect which demand is farthest.

2. Find the weighted 1-median

For one candidate vertex v and demand rows qi with weights wi ≥ 0, the total weighted network distance is:

J(v) = ∑i wi dG(qi,v)

Evaluate every eligible vertex and choose the least-cost one. Hakimi's vertex-optimality result permits a vertex solution for unconstrained network median location with vertex demand. Here the best vertex is C, with cost 2,580 weight·m. The weighted mean distance is 2,580/11 ≈ 234.5 m.

3. Minimize the worst-served demand

R(v) = maxi dG(qi,v)

The vertex 1-center treats the farthest demand as the limiting case; demand weights do not scale the radius. Zero-weight rows still count for minimax. Here the best vertex is D, with radius 360 m, different from the weighted median.

4. Find the exact absolute 1-center

Allow the site to move continuously along edge (u,v) of length L. At distance t from u, a demand row reaches the site through whichever endpoint is cheaper:

fi(t) = min{ dG(qi,u)+t, dG(qi,v)+L−t }

For every edge, each distance has a switch at ti = [d(qi,v) − d(qi,u) + L]/2. Between consecutive switches, the maximum of all distances has the form max(A+t, B+L−t), with minimum at the crossing clipped to that interval (or an endpoint if one branch is absent). Sweep all eligible edges and keep the best. The package uses sorted switches, running maxima and safe edge bounds rather than dense sampling.

5. Solve a single median without storing every distance

The original solver stores a demand-by-vertex matrix. The adaptive single-site solver can instead stream shortest-path batches into one objective vector. With positive total mass W and a feasible reference candidate p, triangle inequality gives:

J(v) ≥ W dG(p,v) − J(p)

If d(p,v) > 2J(p)/W, v cannot improve the incumbent. A safe search cutoff for paths from any positive-weight demand is maxid(p,qi) + 2J(p)/W plus numerical margin. This bound is not an approximation; the package may avoid work without dropping an improving location. A one-site vertex minimax instead streams maximum distances.

6. Replace one center with several representative sites

J(S) = ∑i wi mins∈S dG(qi,s),   |S| = k

With several sites, every demand row is assigned to its nearest eligible site by network distance. A medoid must be an observed demand vertex; a vertex median may be another eligible network vertex. Restricted candidates can represent permissible facilities. In the package, greedy BUILD and bounded improving SWAP produce feasible but not necessarily globally optimal solutions. Exact enumeration is available under a combinatorial limit.

7. Choose how many sites to retain

With exact fixed-k costs, increasing k cannot worsen the optimum. The Python heuristic generates evaluated cost curves and the selection policies act on them; their results depend on the candidate domain, objective and constraints.

Distortion versus representation size

score(K) = J(K)/J(1) + λ(K−1)/(n−1)

Selected by the balanced rule over k=1…4: k = 3 (score 0.683).

This plot uses the live inputs above, one connected component, n=6 distinct demand vertices, and a teaching cap of four sites. The package generalizes the baseline to C populated components, uses max(1,n−C) in the denominator, and treats a zero baseline as a zero normalized cost.

PolicyDecision rule
FixedUse the requested k.
BalancedMinimize normalized distortion plus normalized site-count complexity.
Access budgetFirst evaluated K whose weighted mean access, including connectors, meets the budget.
PenalizedMinimize J(K) + facility cost × K.
GapCompare observed weighted network-medoid loss with reference draws; choose by the one-standard-error rule.

What the network Gap statistic compares

For each component, repeatedly sample reference vertices with replacement, preserving the row weights. The GIS CLI restricts the support to original pre-augmentation vertices inside the observed demand bounding box. Fit heuristic medoids to the observed and reference data. The loss uses unsquared network distance, not the original squared-Euclidean dispersion; a common log floor handles zero loss.

Gap(k) = meanb log Jb*(k) − log J(k)

The smallest k satisfying Gap(k) ≥ Gap(k+1) − s(k+1) is selected, or the tested upper bound is reached. The reference distribution is uniform over eligible vertices, not uniform over road length. Degenerate and inadmissible splits have explicit audit outcomes. Gap is not executed in this browser demo.

8. Allocate sites across disconnected components and groups

Unreachable pairs have infinite distance; the package never invents a connecting road. The adaptive CLI keeps all components by default, with explicit policies:

PolicyMeaning
strictAll modeled demand must be in one component.
largestExclude demand outside the largest component after attachment.
per_componentOne site per populated component.
allocateAllocate a global group budget with at least one site per populated component.
F(c,K) = minj≥1 [ F(c−1,K−j) + Jc(j) ]

Dynamic programming gives the best allocation over the evaluated component curves. It does not certify heuristic component costs as globally optimal. A zero-weight component in a positive-mass median group gets exactly one site, using minimax network-plus-connector access as a secondary objective. Independent demand groups share the routing graph but not each other's inserted candidate vertices. For legacy-compatible snapping, --keep-largest-component filters the graph before attachment, which is not the same as --component-policy largest.

9. Report representation quality, not just center coordinates

For each modeled row i, record its assigned site a(i), network distance, connector offset oi, and access distance d(qi,a(i))+oi. Sum weights per site; report weighted mean and weighted empirical access percentiles, maximum access, and original-input coverage. The adaptive CLI marks excluded and unsnapped rows, and fails by default on unsnapped demand.

DiagnosticInterpretation
site_weightAssigned demand mass; zero-mass sites are visible.
mean_accessWeighted mean including connectors.
max_accessFarthest modeled row, including zero weights.
coverageModeled share of input demand, not just successful snaps.
execution_by_componentWhich finite-site solvers actually ran, evaluated k, pruning enabled, Gap replicates.

The schema net-center-adaptive/5 separates invocation settings from resolved options and actual component execution. No partial group result is published; output is a new JSON file, using hard-link publication.

From math to the package

Legacy pipeline

graph.py → solve.py → distances.py → center.py → legacy CLI result

Adaptive pipeline

graph.py → edge_snap.py → adaptive.py / absolute_groups.py → adaptive_cli.py → audited JSON

The GIS layer supplies metric line geometry and preserves physical edges; parallel edges collapse to their shortest connection in the routing adjacency while remaining physically distinct. The numerical adaptive API accepts a symmetric CSR graph, without mandatory GIS imports. The continuous minimax wrapper calls the established absolute-center solver.

Installation and examples

git clone https://github.com/miraflor/net-center.git
cd net-center
python -m pip install -e ".[gis]"

Original single-center command

net-center roads.gpkg --demand points.gpkg --weight-field population

Adaptive weighted representatives

python -m net_center.adaptive_cli roads.gpkg --demand points.gpkg \
  --weight-field population --group-by region \
  --selection balanced --candidate-domain demand \
  --component-policy allocate --max-centers 12 --out representatives.json

Grouped absolute center

python -m net_center.adaptive_cli roads.gpkg --demand points.gpkg \
  --objective absolute_center --include-offsets \
  --component-policy per_component --out absolute.json

See the runnable numerical example and GIS example. The original command remains unchanged. The adaptive command is a module invocation, not a separate installed executable.

Guarantees and limitations

Supported methodGuarantee
Weighted 1-median / vertex 1-centerExact over declared finite candidates, up to numerical tolerance.
Absolute 1-centerExact continuous minimax for vertex demand, up to numerical tolerance.
Multi-site medianHeuristic by default; bounded exhaustive mode exact over finite candidates and allowed allocation.
Adaptive kSelection over evaluated curves, not a universal optimum.

Networks must be undirected, with positive finite lengths; GIS requires a projected metre-based working CRS and supplied linework. No automatic OSM acquisition, directed/turn-restricted routing, general k-center, capacity constraints or continuous line-density demand. The adaptive multi-site matrix is bounded by a configured size gate, not an overall process memory guarantee. There is no national-scale performance claim.
